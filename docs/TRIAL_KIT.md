# Trial kit (Tugas Akhir trial with 35 respondents)

Build 8 of `docs/PLAN.md` §4. Everything the thesis trial needs, in one place.
The trial promised in the approved proposal (§7 of the plan): **35
respondents** (1 admin, 4 teachers, 30 students: 12 beginner, 10
intermediate, 8 advanced), black-box tests, functional validation, task
scenarios per role, **SUS with a mean above 70**, **731 questions** in the
bank, Midtrans in sandbox mode.

## 1. Accounts and data (trial seed)

| Step | Command | Where |
|---|---|---|
| Rehearse on the emulator | `py -I scripts/seed_trial.py emulator` (twice: nothing changes the second time; `verify` prints the counts) | PC |
| Live accounts and structures | `py -I scripts/seed_trial.py live --credentials <service-account.json>` (try `--dry-run` first) | **owner** |

Live mode writes the 35 accounts (`trial_admin`, `trial_teacher_1..4`,
`trial_student_01..30`), rooms, the price list (only if none exists), the
flyer's timetable (unconfirmed, the Sunday job generates the sessions) and one
8-session voucher with a class day per student (`trial: true`, no invoice, so
they show under "Vouchers without payment"). **Never papers, results or
bookings.** Inputs, both git-ignored and never committed:

- `scripts/trial/passwords.local.json`: `{"admin": "…", "teacher1": "…", …, "student30": "…"}` — the owner hands them out.
- `scripts/trial/respondents.local.csv` (optional): `role,key,email,nameLatin,nameChinese,level`; without it the names are placeholders (`Siswa Uji 01`).

## 2. Question bank (731 questions)

1 practice package of 15 per HSK level (90) + 1 test code per level in the
full format (40 + 60 + 80 + 100 + 100 + 101 = 481) + 2 extra HSK 3 codes (160)
= **731**. Most come from the centre's own simulation papers. **No invented
Chinese content; official papers are never committed** (`local_papers/`).

Routes:

- **Printed paper** → admin **Scan paper** (the paper reader, Build 1B/1C),
  proofread, one recording per listening sheet, keys the reader cannot know
  through the **Answer key** dialog.
- **Digital questions** (the owner's own files) → `scripts/import_questions.mjs`:
  CSV or JSON to `question_bank` docs (and Storage audio), with
  `--dry-run` that reports what it would write.
- **Typed by a teacher** (Build 2B: teachers type their own questions).

Who checks: the teacher of that level reads every question once in the
player before the trial. The checklist below has one row per question; edit
`docs/trial/question_checklist.csv` (source paper, checker, state) and run
`node tool/trial_kit/build_kit.mjs` to refresh this table.

## 3. Task sheets, SUS, black-box tables

| File | What |
|---|---|
| `docs/trial/task_sheet_student.html` | Student tasks (numbered, expected result, pass/fail) — print from the browser |
| `docs/trial/task_sheet_teacher.html` | Teacher tasks |
| `docs/trial/task_sheet_admin.html` | Admin tasks |
| `docs/trial/sus_questionnaire.html` | The 10 SUS items in Indonesian, 1 to 5 |
| `docs/trial/sus_results_template.csv` | One row per respondent: `respondent,role,q1..q10` |
| `tool/sus_score.mjs` | `node tool/sus_score.mjs docs/trial/sus_results.csv` → mean SUS, per-item means, per role |
| `docs/trial/blackbox_template.md` | One black-box table per build from the acceptance walks (generated) |

The task sheets follow the proposal's screens (the 15 screenshots) and
scenario IDs; check them against the proposal's Table 20 in the Word file
when it arrives (§7 of the plan, item 2) and adjust the wording there.

## 4. Screenshots

`node tool/screenshots/run.mjs` against the emulator bundle with the trial
seed saves the proposal's 15 screens to `docs/screenshots/proposal/` with the
file names of `docs/THESIS_PROPOSAL_ASSETS.md`, plus `CONTACT_SHEET.md`.
